## 報告內容

### 01 風險概況
- **KPI 摘要**：情境總數與高／中／低風險數量及比例
- **風險矩陣（5×5）**：橫軸為可能性、縱軸為衝擊，點擊情境編號可跳至該情境的詳細分析
- **各主題風險分布**：以堆疊長條顯示各主題的高／中／低風險數量，並列出各主題平均風險分數

### 02 情境風險識別與分析
每個情境以卡片呈現，包含：
- 情境敘述與識別結果（協定與 Port／威脅類型／SSDLC 要求／管控面向）
- 風險等級與分數（L 可能性 × I 衝擊）
- 風險識別說明
- 防範建議：原表列出的對應防禦＋專家補充建議
- 關鍵字與教材對應頁碼
- 部分情境附有模擬郵件、簡訊或系統紀錄（2-1、2-2、2-4、3-5、4-5、4-7）

上方篩選列可依**主題**、**風險等級**篩選，或以關鍵字搜尋。

### 03 總結與建議
- 整體風險結論
- 六大風險主軸：明文傳輸與服務暴露、身分驗證與帳號安全、人為因素與社交工程、敏感資料保護、服務可用性與營運持續、第三方／未知漏洞與治理
- 改善優先順序：立即（0–1 個月）、短期（1–3 個月）、中期（3–6 個月）
- 結論與評估方法說明

## 評估方法

**風險分數 = 可能性（1–5）× 衝擊（1–5）**

| 等級 | 分數 |
| --- | --- |
| 高風險 | ≥ 15 |
| 中風險 | 8 – 14 |
| 低風險 | ≤ 7 |

- 主題 1（TCP Port 識別）、主題 2（資安威脅）：評估情境本身暴露的風險
- 主題 3（SSDLC）、主題 4（資安管控模式）：此兩主題為控制措施，評估的是「若未落實該措施」時組織將面臨的風險

> ⚠️ 可能性與衝擊分數為依情境描述所做的專業判斷，原始對應表並未提供。實際導入時應依組織資產與現況重新校準。

## 修改資料

所有情境資料集中在 HTML 檔案 `<script>` 區塊內的 `DATA` 陣列，每筆欄位如下：

| 欄位 | 說明 |
| --- | --- |
| `g` | 主題編號（1–4） |
| `id` | 情境編號，例如 `"2-2"` |
| `ident` | 識別結果 |
| `tag` | Port 號或管控面向（選填） |
| `L` / `I` | 可能性／衝擊（1–5），分數與等級會自動計算 |
| `scene` | 情境敘述 |
| `risk` | 風險識別說明 |
| `source` | 原表對應防禦（主題 1 為技術特性） |
| `tips` | 專家補充建議（陣列） |
| `kw` | 關鍵字（以逗號分隔） |
| `page` | 教材對應頁碼 |
| `mock` | 模擬郵件／簡訊／日誌（選填） |

修改 `L`、`I` 後，KPI、風險矩陣、主題分布與總結開頭的數據會自動更新；但**結論段落**、**改善優先順序**與 `THEMES`（六大風險主軸）為手動撰寫的文字，若評分大幅調整，請一併檢查。

> 注意：在 `mock` 文字中若需顯示 HTML 標籤（如 `<script>`），請寫成 `&lt;script&gt;`，否則會中斷頁面的程式碼。
